# ブリストルログ

変えてみたことと、からだの変化を記録して、**その前後を見くらべる**ための iOS アプリです。

日記でも服薬管理でもなく、「何かを始める・やめる・変更する」ときに期間を区切って記録し、
前と後でどう違ったかを振り返ることに寄せています。

> 変えてみたことと、からだの変化を記録。
> 毎日の記録から前後の変化を振り返れます。

## コンセプト

観察の単位は **プラン** と **フェーズ** です。ひとつのプランを、

- **いつもの状態**（何かを始める前の普段の状態）
- **試している期間**
- **お休み期間**

といったフェーズに区切って記録し、フェーズごとの平均を「いつもの状態」と比べます。

最初のユースケースは、排便の回数や状態と服薬の経過観察です。
ただし薬に限定しない作りにしてあり、観察の対象は **薬 / サプリ / 食事 / 運動 / 生活習慣 / その他**
から選べます。内部でも `Medication` ではなく `ObservationTarget` を基本概念にしています。

UI は日本語のみです。

## 主な機能

**今日** — 今のプラン・フェーズ・開始から何日目かを表示します。「＋ 排便を記録」から、
便の状態（ブリストル便形状スケール 1〜7）を選んで保存するまで数秒で終わるようにしてあります。
時刻は現在時刻が入っていて、腹痛・急な便意・メモは任意です。観察対象の実施チェックと
1 日のまとめ（全体的な体調 / 腹部の調子 / メモ）も同じ画面にあります。
排便が 0 回だった日は「排便はなかった」を押して明示できます。

**経過** — Swift Charts の折れ線グラフに、フェーズを背景の帯・境界の破線・平均の破線で重ねて表示します。
指標は排便回数・ブリストル値・腹痛・急な便意を切り替えられます。
フェーズごとに日数・平均排便回数・平均ブリストル値・腹痛平均・急な便意平均を出し、
それぞれに最小〜最大の範囲を添えて、「いつもの状態」との差と変化率を並べます。
観察対象の実施日数もフェーズごとに出し、実施した日と実施しなかった日が
どちらも記録されていれば、同じ期間の中でその 2 つを見くらべます。

**カレンダー** — 月ごとに記録の有無・排便回数・フェーズが分かります。日付をタップすると
その日の記録を確認・編集・削除できます。

**設定** — 観察プラン管理、観察対象管理、記録項目、通知、データ管理、アプリについて。
1 日 1 回の記録リマインダーの ON/OFF と時刻、フェーズごとに集計から外す開始直後の日数を
ここで変えられます。

## 集計の考え方

数字の出し方を曖昧にすると振り返りの意味がなくなるので、次のように決めています。

- **平均の分母は「記録がある日数」** です。記録のない日を 0 回と数えると平均が実態より低く出るため、
  集計から外します。まとめだけ書かれた日は「排便 0 回」として数えます。
  画面には「7日間（記録 6日）」のように、何日ぶんを基準にしたかを併記します。
- **グラフは記録のない日に点を打ちません。** 線をつなぐと、その日が 0 回だったように読めてしまうためです。
- **ブリストル値・腹痛・急な便意の平均は、記録 1 件ごとの平均** です。日ごとの平均をさらに平均すると、
  回数の多い日と少ない日が同じ重みになってしまいます。
- **記録はフェーズに紐づけず、日付から導出** します。あとからフェーズの期間を直しても、
  集計がその場で正しく計算し直されます。
- **排便 0 回の日は、明示されたときだけ 0 として数えます。** 記録が 0 件なのは「なかった」と
  「まだ書いていない」の両方がありえるためです。「排便はなかった」を押した日だけを 0 回にします。
- **平均には最小〜最大の範囲を併記** します。平均だけだと、差が日々の振れ幅の内側なのか
  外側なのか読めないためです。
- **差を文章にするのは、両側に 7 日ぶんの記録がそろってから** です。それまでは差の数値は出しますが、
  「少なくなっています」のような一文は出しません。1 日分の記録から割合を言い切らないためです。
- **観察対象は実施日数のまま出し、率にはしません。** チェックのない日は「実施していない」ではなく
  「記録していない」なので、率にすると実態から離れます。
- **フェーズごとに、開始直後の数日を集計から外せます。** 始めてすぐは変化が出ないことがあるためです。
  外した日の記録は消えず、グラフにも点が出ます。平均と比較の分母からだけ抜きます。

## ご注意

本アプリは日々の記録・振り返りを目的としたもので、診断や治療方針を提供するものではありません。
服薬や症状については医師・薬剤師に相談してください。

画面に出るのは記録から計算した数値とその差だけです。
「効いています」「続けてください」のような判断は表示しません。

## プライバシー

- アカウント登録なし
- 外部サーバー・外部 API なし
- データは端末内にのみ保存（SwiftData）

他端末との自動同期には対応していません。機種変更のときは、設定 > データ管理 > データの引き継ぎ から
引き継ぎファイル（写真も含む JSON）を作り、新しい端末で復元します。

## 動作環境

- iOS 26.0 以降
- Xcode 26 / Swift 5 言語モード
- 外部ライブラリなし（SwiftUI・SwiftData・Swift Charts・UserNotifications のみ）

## ビルド

```bash
xcodebuild -project TameshiteLog.xcodeproj -scheme TameshiteLog \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=26.0' build
```

インストールされているランタイムが複数ある場合、同名のデバイスが各バージョンに存在するため、
`OS=` を明示しないと意図しないランタイムが選ばれることがあります。

DEBUG ビルドでは `-sampleData` を付けて起動すると、6 週間ぶんの架空データが入った状態で立ち上がります。
画面の確認にはこれが一番早いです。

```bash
xcrun simctl launch "iPhone 17 Pro" jp.hibiki.bristollog -sampleData
```

このデータは UI と動作の確認用に作った架空のもので、医学的な効果を表すものではありません。

## 構成

```
TameshiteLog/
  Model/       SwiftData モデルと各種スケール
  Analytics/   集計・比較の純粋計算（ビューにも永続化層にも依存しない）
  Service/     複数モデルにまたがる更新、通知、サンプルデータ
  Feature/     Today · Trend · Calendar · Settings · Onboarding · Shared
  Support/     日付・数値の書式、カレンダー補助、フェーズの配色
```

設計上の決まりごとは [CLAUDE.md](CLAUDE.md) にまとめてあります。

## MVP の範囲外

次の機能は入れていませんが、あとから足しやすいように責務を分けています。

Widget / Apple Watch / iCloud 同期 / HealthKit /
服薬リマインダー / 任意の症状項目 / 食事・睡眠の記録

CSV 出力と PDF レポートは実装済みです（経過画面の「書き出す」から）。
